What you can build

The plugin exposes Game Jolt API operations through a Blueprint function library and manager classes.

Player authentication

Authenticate a player with their Game Jolt username and user token before making user-specific requests.

Sessions

Open and close gameplay sessions and ping active sessions so Game Jolt can track play activity.

Trophies

Fetch trophy information and build achievements into your gameplay flow.

Leaderboards

Submit player or guest scores, fetch score tables, and look up score ranks.

Cloud data

Read and write global game data or data associated with an authenticated user.

Blueprint + C++

Use Blueprint nodes for visual workflows, or call the same functionality from native code.

Install the plugin

Install the plugin into a project, then let Unreal build the module for your engine version.

  1. Download a release

    Open the GitHub Releases page and download the latest plugin archive. If no packaged release is available, use the repository source.

  2. Place it in your project

    Extract the GameJolt plugin folder into YourProject/Plugins/GameJolt/. Create the Plugins directory if needed.

  3. Generate project files and compile

    Right-click the .uproject file and choose Generate Visual Studio project files where available. Open the project and allow Unreal to compile the plugin. Install the matching C++ toolchain for your engine version.

  4. Confirm it loaded

    In Unreal Editor, open Edit → Plugins and verify GameJolt is enabled. Restart the editor if prompted.

Important: this is a C++ plugin. A pure Blueprint-only project must first be converted to a C++ project by adding a C++ class and completing an initial compile.

Configure Game Jolt API

Set your game's API credentials once in Project Settings, then authenticate players at runtime.

  1. Find your credentials

    Open your game on the Game Jolt dashboard and find Game API → API Settings. Copy the Game ID and private key.

  2. Enter credentials in Unreal

    Open Edit → Project Settings, locate the Game Jolt API section under Plugins, and enter the Game ID and private key.

  3. Authenticate players safely

    Ask the player for their Game Jolt username and user token, then call Login. Do not hard-code a player's token, print credentials to logs, or commit private credentials to source control.

The game's private key is sensitive. Keep it out of public repositories and logs. Only distribute builds that use credentials according to Game Jolt's API rules.

Blueprint workflow

The Blueprint function library groups API nodes under the Game Jolt category. Most operations complete asynchronously and report success or an error message through their completion delegate.

Typical startup flow

Event BeginPlay
  → GJ Login (Username, Token)
      → On Complete
          → Branch (bSuccess)
              True → GJ Open Session
              False → Show login error

Close the session when your game flow ends, such as when returning to the menu or shutting down the gameplay session.

C++ usage

Include the plugin's Blueprint function library header and pass a valid world-context object. The example below shows the callback pattern; match the function signature to the version installed in your project.

#include "UGameJoltBlueprintLibrary.h"

void AMyPlayerController::AuthenticatePlayer(
    const FString& Username,
    const FString& UserToken)
{
    FOnAuthUserComplete OnComplete;
    OnComplete.BindLambda(
        [](bool bSuccess,
           const FGameJoltUser& User,
           const FString& ErrorMessage)
        {
            if (bSuccess)
            {
                UE_LOG(LogTemp, Log,
                    TEXT("Authenticated: %s"), *User.username);
            }
            else
            {
                UE_LOG(LogTemp, Warning,
                    TEXT("Game Jolt login failed: %s"), *ErrorMessage);
            }
        });

    UGameJoltBlueprintLibrary::Login(
        this, Username, UserToken, OnComplete);
}
Callbacks are asynchronous. Handle both success and failure, and avoid assuming the user is authenticated until Login reports success. Always check the installed header for the exact delegate and function signatures.

Submit a score

FOnDataStoreOpComplete OnComplete;
OnComplete.BindLambda(
    [](bool bSuccess, const FString& ErrorMessage)
    {
        if (!bSuccess)
        {
            UE_LOG(LogTemp, Warning,
                TEXT("Score submission failed: %s"), *ErrorMessage);
        }
    });

UGameJoltBlueprintLibrary::SubmitScore(
    this, TEXT("5000 Points"), 5000, 0, OnComplete);

All C++ library functions require a valid world-context object as their first argument. An actor or user widget is commonly suitable.

Engine compatibility

The intended compatibility target is Unreal Engine 4.20–4.27 and Unreal Engine 5.0–5.8. Treat this as the target range, not a claim that every version has been independently built and tested.

Engine familyTarget rangeVerification status

For a new engine version, compile the plugin from source in a clean C++ project and smoke-test login, session open/close, score submission, and datastore calls. Report tested versions in the release notes.

Troubleshooting

The plugin won't compile

Confirm the plugin is under the project's Plugins/GameJolt directory, your C++ toolchain matches your Unreal version, and the project files were regenerated. Check the first compiler error rather than later cascading errors. Include your engine version and the full first error when asking for help.

Login succeeds but user-specific calls fail

Wait for the Login completion callback to report success before requesting trophies, opening sessions, or reading/writing user data. Verify the username and user token in Game Jolt.

Sessions stop appearing active

Game Jolt expects active sessions to be pinged periodically. The current README documents automatic pings every 30 seconds and a 120-second timeout; confirm this behavior in the exact plugin build you use.

Cloud data isn't returned

Check whether the operation is global or user-specific, confirm authentication for user data, and verify the datastore key. Handle an empty value separately from a failed request.

Where do I report a bug?

Open the GitHub Issues page and include your Unreal version, plugin version, steps to reproduce, and relevant logs with tokens and private keys removed.
